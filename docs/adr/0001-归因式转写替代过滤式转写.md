# 归因式转写替代过滤式转写

转写遇到"不属于用户口述"的声音（外放视频、播客、电视）时，业内惯例和团队初版方案都是过滤掉。我们决定反过来：**保留并标明来源**，因为 OpenMy 是上下文引擎而非对话记录仪——用户听到的内容（看了什么视频、听了什么播客）本身就是当天上下文的一部分，过滤丢信息，混入错归因，标记来源两全。

同理，转写对"拿不准的内容"不再二选一（硬转或放弃），而是三值：确定内容直接输出、存疑内容带记号输出、完全听不清标 [无法识别]。存疑内容由蒸馏后的转写确认环节人机对质敲定（一次最多 5 个，只问影响日报的），确认结果回写纠错词典——不确定性成为词库的进货渠道。

归因分三类：佩戴者说的、在场他人说的、设备放的。佩戴者与他人的区分依据物理特征（佩戴式麦克风离佩戴者最近、声音最清晰），不做"他人是谁"的细分——完整说话人分离已验证超出 Gemini 能力。

## Considered Options

- **过滤式**（被否决）：外放一律删除、拿不准的标 [无法识别]。干净，但丢掉"用户听到的"上下文层，且二值标注导致模型在"硬凑"和"放弃"间总是选硬凑。
- **混入式**（旧行为）：不区分来源全部转写。外放冒充用户对话，造成日报第一人称归因错误（实例：外放教程被写成"我在研究零代码 AI 工作流"，朋友的近况被写成"我白天在电子厂上班晚上送外卖"）。

## Consequences

- 转写输出引入新标记（存疑记号、外放标记、我/他人归因），cleaner、scene_quality、distiller、briefing 全链路需适配，标记格式一旦定下难以更换。
- 蒸馏层从"猜归因"变为"读归因"，第一人称错误的根治依赖转写层标记的可靠性。
- 归因标记（尤其佩戴者二分）的可行性未经验证，进入正式 prompt 前必须通过固定测试集对照实验。
- 裁决一切冲突的原则是"宁漏勿假"：幻觉的代价高于遗漏，因为日报是记忆替代品，假记忆不可感知。
